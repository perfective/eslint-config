== Overview

The purpose of this configuration is to create a subset of the JavaScript and TypeScript languages,
to enforce code quality, readability, and maintainability.
It is based on the ideas that:

* Code maintainability and support cost more than original development.
* Code readability is more important than the speed of writing it.

It brings the https://www.goodreads.com/book/show/18197267-don-t-make-me-think-revisited[Don't Make Me Think]
approach from web usability to code,
and assumes that:

* Simple code is better than complex code.
* Certainty is better than uncertainty.
* Explicit statements are better than implicit statements.

== Language options

The `languageOptions()`, `javascriptLanguageOptions()`, and `typescriptLanguageOptions()` functions
set the same global variables (`languageOptions.globals`),
so rules that depend on the environment
(for example, `unicorn/prefer-global-this` or `n/prefer-global/*`)
recognize browser and Node.js global variables.
`perfectiveEslintConfig()` applies `languageOptions()` to `ecmaFiles`.

[cols="1,2,1"]
|===
| Globals | Source | Value

| Browser
| `globals.browser` from the link:https://github.com/sindresorhus/globals[`globals`] package
| `'readonly'`, except the `on*` event handlers and `location`, which are `'writable'`

| Node.js (ES module)
| `globals.nodeBuiltin` from the link:https://github.com/sindresorhus/globals[`globals`] package
| `'readonly'`
|===

The CommonJS variables (`require`, `module`, `exports`, `__dirname`, and `__filename`) are not defined,
as the configuration lints ES modules (`sourceType: 'module'`).
Code that runs only in one environment or needs other globals (for example, workers)
can override `languageOptions.globals` in its own config.
